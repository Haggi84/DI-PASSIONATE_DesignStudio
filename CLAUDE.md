# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Package Studio: a FreeCAD 1.x workbench (Python, FreeCAD's bundled 3.11) for chip packaging *assemblies* — GDS chips with a PDK technology (several per import), housings from a library, lids and boards as STEP, several packages per document — placed and moved parametrically, with pads, ports, symmetric bond wires and one material system, to a ready-to-run openEMS / EMerge / Palace package written by the vendored OTTER add-on, and an EM assistant (Ollama by default). It started as a copy of Package Designer (`%APPDATA%\FreeCAD\v1-1\Mod\PackageDesigner`) and took the EM simulation and assistant from DI-PASSIONATE (`Program Files\FreeCAD 1.1\Mod\DI-PASSIONATE-FreeCAD`, `core/em`, `emsim`); both are kept separately and can be installed beside it. It lives in FreeCAD's **user** Mod folder (`%APPDATA%\FreeCAD\v1-1\Mod\PackageStudio`). Dependency: `gdstk` in FreeCAD's Python. OTTER is in `thirdparty/otter` (GPL-3.0, copied unchanged from DI-PASSIONATE: never edit it, update by copying).

## Commands

```powershell
# All headless tests (exit 0 = pass); report also in tests\results.log
& "C:\Program Files\FreeCAD 1.1\bin\freecadcmd.exe" tests\run_all.py
# One module
& "C:\Program Files\FreeCAD 1.1\bin\freecadcmd.exe" -c "import sys; sys.path[:0]=['tests','.']; import test_em as t; r=t.run(); print(sum(x.passed for x in r),'/',len(r)); [print('FAIL',x.name,x.message) for x in r if not x.passed]"
# GUI smoke test: real FreeCAD window, throwaway profile, drives every command and panel, writes a real OTTER package
& "C:\Program Files\FreeCAD 1.1\bin\python.exe" tests\run_gui_smoke.py
```

`run_all.py` picks up every `tests/test_*.py` automatically (575 checks; the MirrorSemi check skips until a model is in the download cache). The GUI smoke test has 67 checks; `tests/gui/system_macro.py` the MCM & System toolbar (6 checks); `tests/gui/element_macro.py` drives the Element Forge against a fake streaming Ollama (16 checks). Tests use `_harness.TestCase` (`check`, `near`, `skip`); expected values are worked out by hand in each module's docstring, never taken from the code's own output. test_flow and test_housing take a few minutes each.

## Architecture

Everything is under the one package `pkgstudio` — FreeCAD puts every Mod folder on `sys.path`, and the sibling add-ons use generic top-level names. Commands are `PS_…`, settings `User parameter:BaseApp/Preferences/Mod/PackageStudio` (EM: `…/PackageStudio/EM`).

- **`core/`** — no GUI, no document. As in Package Designer: `tech`, `layout`, `mesh`, `clusters`, `pads`, `symmetry`, `bondwire`, `contacts`, `edgeport`, `wirerules`, `materials`, `housing`, `jedec`, `catalogue`, `placement`, `solids`, `export`, `gmsh_c`, `touchstone`; `palace` now only for its layout helpers (`clip`, `clip_to`, `merge_vias`, `max_cell`) — its mesher and config are no longer called from the GUI. New: `elements` (housing specs as data: the field schema with datasheet symbols, `validate` → `Issue`s with fixes, `geometry` — shared with `jedec.build`, it stops leads clear of the neighbouring row: before, 12 of 25 catalogue packages had corner leads sharing copper —, `auto_repair`, the user library as JSON files, `json_schema` for the model; FreeCAD-free), `pinlist` (designer intent: `Pin`, `Intent`; CSV / xschem `.sch` top pins / LEF readers, `merge`, `guess_kind`, `die_to_die_nets`), `package_lvs` (`check(intent, wires, leads, neighbours)` → findings + lead nets: open, short, wrong lead, unknown pad, nc bonded, no lead, rf return, unused), `bonding_diagram` (SVG + CSV wire list from a plain data dict), `kicad_pcb` (S-expression parser; `read` → Board: stack-up, Edge.Cuts outline chained, footprints/pads (y flipped, footprint rotation applied), tracks incl. arcs, vias, zone fills, fp_poly/gr_poly copper; `z_ranges`), `kicad_board` (Board → pcb.Pieces: dielectrics with holes, copper per layer and net, SMD pads as `Land`s grouped by reference, optional region + centring), `kicad_export` (`.kicad_mod` + `.kicad_sym` text, KiCad 8 format), `circuit_model` (scikit-rf vector fitting: tries poles 1..14 × constant on/off, takes the first *passive as fitted* within tol — passivity_enforce wrecked fits in tests; SPICE subckt, xschem symbol, `check_against` with ngspice), `validation` (P370 FD quality, P370 NZC 2x-thru de-embedding, compare, plot, Markdown report), `mcm` (multi-chip modules: `arrange` dies in a row/column/corner to corner, `check` paddle margin, die-to-die gap, finger keep-outs; `share_leads` — a weighted Voronoi split of the lead ring among the dies; `pair_anchored` — order-preserving pairing between fixed anchors; `assign_arcs` — exhaustive cut of the lead ring into one arc per die for 2–3 dies, anchors and per-segment capacity respected, least angular cost), `pcb` (generated boards: `qfn_lands` shortens corner lands to keep 0.2 mm to the other row (the QFN-24 4x4 and QFN-40 6x6 corner lands touched); `Stack`, PC/104 outline and holes, `qfn_lands`, `footprint`, `trace`, `gcpw` with via fence, `box`/`header`/MMCX/SMA bodies, `cutout` for an EM region; FreeCAD Part), `cubesat` (1U structure, panels, rods/spacers, patch; `CDS_1U` limits), `moving` (offset placements in the surface an object stands on: X/Y = the container's X/Y laid into the surface, the turn about the base's Z through the bottom centre; `rebase` for objects moved by other means; `overlaps`), `otter_path` (puts the vendored OTTER first on `sys.path`, drops a foreign copy — DI-PASSIONATE has its own).
- **`app/`** — the FreeCAD document, works headless.
  - `model`: roles via `PkgRole`. **Several packages**: `packages`, `new_package`, `package_for_housing` (a housing always gets a package of its own); `package(doc)` is the first one. **Chips import loose** at the top level, `CHIP_GAP` beside the loose ones (`_free_x`); `assembly_owner(obj)` = the Package of a housing or lid, the Board, or None; `move_into` reparents keeping the global placement; `common_owner` for wires; `global_bbox`.
  - `placing.place(obj, faces, turn, onto)`: reparents into `owner_for(obj, onto)` (chip → the housing's package or the board; package → board), then `moving.set_base`, `wires.regroup`.
  - `moving`: the Position properties (`PlaceBase` hidden, `OffsetX/Y`, `OffsetAngle`), `nudge` / `drag` / `set_offsets` / `reset`, `rebuild_wires` (only the wires on the moved objects), `overlap_report`, `OffsetObserver` (property-editor edits; wires rebuilt through a QTimer, never inside the callback), `install_observer` (from the workbench).
  - `netlist`: `load` (csv/sch/lef), `match_dies` (label, top cell, GDS stem), `apply` (PadNet/PadKind on chip pads), `assign` (fixed leads as anchors + die-to-die chains + crossing-free rest via `wires.auto_pair_mcm(fixed=)`), `lvs` (sets LeadNet).
  - `bonding`: diagram data from the document, `export` → SVG + CSV.
  - `kicad`: `import_board` (Board container from a .kicad_pcb), `export_package` (lands from the element spec numbered by the lead whose finger lies on them; footprint, symbol with LeadNet names, STEP with dies and wires).
  - `boards`: `make_board` from core.pcb pieces (one Part::Feature per piece, `BoardPiece`/`BoardGroup` props, grouped), `place_package` onto a footprint's lands.
  - `system`: role "system" (App::Part); `make_cubesat`, `add_board` (by top height; rebuilds rods and spacers), `check` → `Finding`s + summary: envelope/protrusion, collisions between modules (each Board, each structure group), stack room above/below each board, mass (density × volume or `MassOverride` g) and centre of gravity against `cubesat.CDS_1U`.
  - `housings` MCM: `place_chip(offset=)`, `place_chips`, `chips_on`, `check_mcm`; `rebuild` keeps each die where it sat on the paddle. `wires.auto_pair_mcm` (share leads, pair each die round its centre), `wires.die_to_die`; a die-to-die wire's second bond is judged by 3.2.1.4a (`WireSpec.die_to_die`).
  - `element_ai`: Ollama fills in an element spec (structured output = `elements.json_schema()`), streamed with `on_field` per completed value, up to 2 repair rounds with the validation errors; own urllib transport (no proxy for localhost), FreeCAD- and Qt-free.
  - `housings`: `from_jedec`/`from_spec_dict` keep the spec as `ElementSpec` (JSON); `spec_of`; `rebuild` in place (pads matched by pin number, wires stay; a chip on the paddle is re-placed keeping its offsets); `from_solids` puts each housing into `package_for_housing` and `_beside_others` (2 mm below); `place_chip` moves the chip into the housing's package.
  - `wires`: one wire group per owner (`_group(doc, owner)`; the top level for wires between two owners), `regroup`, `wires_of(objs)`, `auto_pair` chip by chip with the leads of its own owner.
  - `materials`, `ports`, `exporting` as in Package Designer.
  - EM: `em_materials` (every library and PDK material registered with OTTER under its own name; σ ≥ 1e4 S/m is a conductor; `register_scaled` for via fill), `em_model` (the flat simulation document: `physical_objects` + exact chip metal per `ChipRegion` (default round the wired pads, the top two metals and the vias between, at most `MAX_POLYGONS`), ports, an air box at λ/4; OTTER's model via `describe_body` / `refresh_model`; `port_contacts`), `em_project.EmProject` (an OTTER Project; `remember_materials` writes back to the Material property; `excitation_axis`), `readiness` (`check(doc)` before a build, `check_model(sim)` after; a Finding has level, message, fix, objects (assembly Names), model_objects (EM model labels)), `fixes` (a Suggestion per finding: shapes to draw as problem / conductor / proposed, objects to select, Actions that apply a fix, the command that fixes it by hand; `port_span` finds the conductors a lumped port should join in its footprint, as OTTER's box-touch check counts it, and `apply_port_span` resizes the assembly's port through its own frame), `assistant` (DI's urllib transport for Ollama / Claude / Gemini, plus `<readiness>` in each turn).
- **`gui/`** — `commands` (12 toolbar commands in work order + `MENU_ONLY` Layers and Export; `toggle_dock` for the EM docks), `panels` (`PlacePanel`; `_SurfacePanel`, the shared face chooser with its grid; `PadsPanel` (pads + contact points); `PortsPanel` (face ports + edge ports); re-exports `WiresPanel`, `MaterialsPanel`, `MovePanel`), `move_panel` (a table of movable objects, steps, typed offsets, `_Drag` with its own event loop), `fix_preview` (a suggestion drawn as temporary PS_FixPreview features in the assembly, zoomed to; removed on the next click, on apply, when the panel hides), `element_panel` (the Element Forge: describe → Generate/Change in a QThread, fields fill as they stream, ≈ assumed values, live validation + build preview `PS_ElementPreview`, Save / Insert / Update housing), `flow_cmds` (the Design flow toolbar: Pin list & LVS panel, Bonding diagram (SVG→PDF via QtSvg), KiCad board, KiCad library, Circuit model, Compare with measurement), `system_cmds` (the MCM & System toolbar: Arrange dies, Wire the MCM, PC/104 board, CubeSat 1U, Into the system, Integration check panel), `em_panel` (a _FixBox under the readiness list and under OTTER's checks; readiness, chip metal presets, the OTTER steps, `make_all`), `assistant_panel`, `em_state` / `em_preferences` / `otter_runner` (DI's, re-pathed), `housing_dialog`, `browser`, `export_dialog` (geometry only — Package Designer's Palace EM tab is gone), `edge_ports`, `port_view` (keep its path: saved documents reference `pkgstudio.gui.port_view.PortView`), `face_grid`, `selection`.

The view and the exports are deliberately independent: the view shows meshes (or cluster blocks) built from the polygons; the exports and the EM model rebuild exact geometry from the same polygons. A chip remembers its `GdsPath` and `TechFolder`.

Network: `core.catalogue` (only on an explicit user action) and the assistant (only when asked; Ollama on localhost by default). MirrorSemi files must never be committed or bundled.

## FreeCAD pitfalls this code works around (each one cost a debugging session)

- `obj.getGlobalPlacement()` returned only the object's own placement during a recompute. Use `model.global_placement()` (walks `getParentGeoFeatureGroup()`).
- A plain `App::PropertyLink` from an object inside an `App::Part` makes that Part claim the target — it pulled pads out of their chip. Cross-container links are `App::PropertyLinkGlobal`.
- `Shape.transformShape()` with a rigid matrix stores a location, which a feature's recompute drops. Build geometry directly in the target frame (see `BondWire.execute`).
- OCCT's default `BoundBox` on B-spline shapes is loose; use `optimalBoundingBox()` when it matters, and don't let wires into a package's extent.
- Pipe sweeps: give `MakePipeShell` the plane's normal as binormal; Frenet frames differed between a wire and its mirror image.
- Gmsh: size wires by their diameter on their own points (`MeshSize{PointsOf{...}}`); curvature sizing hung on swept surfaces.
- Binary STL (used to load display meshes fast) is 32-bit — display only; never measure exact values from layer meshes.
- Bond-wire solid: `MakePipeShell` with several sections along one spine raised `NCollection_Array1::Value` (with locations) or twisted (without); a loft through many sections wiggled (70 % too much volume); fusing per-edge sweeps took 1.4 s a wire. What works: sweep each spine edge between explicit sections at BOTH its ends (a carried-along section turns slightly on a non-planar spine and then does not sew), drop the inner planar caps, `Shell.sewShape()` — 0.05 s. Sections must share one parametrisation (points evenly spaced along the outline; by angle overshot a thin stadium's round edges by 6 %).
- A shape touching a plane only along a line breaks booleans and meshers: bond feet are sunk 0.1 t and cut flat (`bondwire.SINK`).
- `freecadcmd` imports a script as a module by its file name: never name a script after a stdlib module (`inspect.py` silently did nothing).
- Gmsh in-process can crash the whole interpreter (`Mesh.OptimizeNetgen` raised an access violation inside gmsh.dll on 6_final). Never call `core/gmsh_c` from FreeCAD itself.
- Via clustering for display (10 µm gap) is wrong for EM: it merged a whole corner of vias into one block. The EM model merges via arrays with `palace.merge_vias` (grow 0.75 via widths, unite, shrink back).
- The Layers dock refreshes from `FreeCAD.ActiveDocument`, not from a document passed in.
- A port turned 90° (any port standing on an edge) reads its BoundBox a rounding step off (cos 90° = 6e-17): 0.19999999999999998 for a lead top at 0.2. OTTER keeps port planes as exact mesh lines, so that gave a 1e-13 um cell and an FDTD timestep of nothing. `em_model._snap_ports` rebuilds every port face from its corners with no placement, snapped to body faces within 1e-9 mm. Translating the shape does not help: it adds a location, and the extent read through it is off again.
- OTTER's `add_lumped_port` defaults to direction z; a port lying flat (lead to paddle) then "has zero length". `em_project.excitation_axis` hands over each port's own excitation axis.
- `placing.place(chip, faces)` without `onto` leaves the chip loose: the package then moves away without it and its wires stretch across the board (Gmsh hung meshing them in test_flow). The Place panel always passes the selected face's object.
- PySide6 wants `QtCore.Qt.UserRole`, not the number 32, for item data.
